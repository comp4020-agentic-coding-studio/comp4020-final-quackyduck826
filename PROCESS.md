# Process overview

I started with a plan rather than code: [`a935ac5`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/a935ac5) sketched the concept (an .io-style fish game, bots standing in for other players) and what "good" meant for the week before anything existed.

One of the first things I did was add two clauses to `CLAUDE.md` ([`0f1ebef`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/0f1ebef)): not to edit `PROCESS.md` or anything in the general documentation or reflections folder without permission, and to commit and push often but only update the Fly server when asked. Because I take a more hands-off approach to guiding Claude, this meant that when running free in auto mode it wouldn't get ahead of itself and invent reasons it has to do things a certain way just because it's following what's in the files it had itself written moments before. The commit/fly clause mattered especially when making large batches of purely visual changes, where running and checking the local dev server on my end is much faster than updating Fly every time.

From there the loop was plan → execute → check in. I built the server and client ([`8eb7c42`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/8eb7c42)...[`acc5a37`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/acc5a37)), deployed to Fly, played it, and came back with a list of what felt off.

**Stack decision**: plain Node running TypeScript natively, serving vanilla JS from `public/`, canvas 2D for rendering — no framework or bundler, so the whole stack fits in one head. The leaderboard persists as a JSON file on the Fly volume at `/data`, not a database: writes are small, infrequent, single-process, and a DB service would be overhead with no payoff yet. I'd reach for SQLite on the same volume first if concurrent writes or richer queries ever mattered, and record that switch here. I reverified the leaderboard survived every redeploy, since that's the one thing a bad deploy could quietly wipe.

Most of the work after was small and visual, against a live dev server so I could viually check each change. The fish rendering went through several passes chasing a shape that reads as a fish from above — articulated tail first ([`7717fee`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/7717fee)), merging the tail segments into one piece ([`df3ffa6`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/df3ffa6)), then widening the fins ([`1a4c6db`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/1a4c6db)). Screenshots of those stages are below.

I treated bugs and polish separately. One bug: bots jittered left-right choosing between two threats to flee, traced to the AI recomputing the nearest target every frame with no memory — fixed with sticky target selection and a turn-rate cap ([`7524d8f`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/7524d8f)...[`8591feb`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/8591feb)). Polish came from brainstorming what would make the game feel finished: a live leaderboard, fish-pun bot names, a dash cooldown bar, the pond.io rebrand ([`a6402af`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/a6402af)...[`0a2c848`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/0a2c848)).

**Crit 9 multiplayer decision**: real-time play is server-authoritative over WebSockets, the server running the same `sim.js` tick loop and broadcasting snapshots, because the Fly setup is already one single process so there's no scaling cost to it owning the whole simulation, and it reuses the existing pure sim code almost unchanged.

**Crit 10 distinguishability decision**: the brief's test is whether two pod members are tellable apart purely from server logs, with no UI in front of the presenter. The server already had everything it needed to know who's who — each connection owns exactly one `Player` with a stable id, name and colour from `room.ts`'s `handleConnection`/`finishRun` — so this was a logging problem, not an architecture one. I added `src/server/actionLog.ts`: one `logAction()` call that writes a JSON line to stdout (what `flyctl logs` tails live) and appends the same line to `/data/actions.log` on the existing Fly volume, following the same serialised-write pattern as `leaderboard.ts` so concurrent events can't interleave mid-line. It's called at join, disconnect, death/give-up, and player-eats-player ([`f0f8775`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/f0f8775)) — deliberately not on every food pellet, which would flood the stream at the 20Hz tick rate without adding anything narratable.

**Permissions reasoning**: each WebSocket connection maps to at most one `Player` (`conn.player` in `room.ts`), and every inbound message is applied only to that connection's own player — `steer()`, `triggerDash()` and the quest tallies all read and write through `conn.player`, never by an id the client supplies. A client literally cannot address another player's entity: there's no message type that takes a target player id for anything mutating. The only state a client can read about *other* players is what `publicPlayer()` already broadcasts to everyone (position, size, name, colour, cosmetic hat) — nothing private exists per-player beyond the live connection's own socket, so there's nothing further to restrict.

**Post-crit changes**: after having a group of people actually play the game, a few glaring problems needed fixing — bots were too easy to avoid, since they didn't chase all the way to the edge of the playable area ([`67b4c50`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/67b4c50)), and the dash function was way too punishing because it didn't give enough of a boost for how much it slowed you down afterwards originally([`bb59598`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/bb59598)). Something else that helped significantly in making the game more challenging was functional zoom: your field of vision starts much smaller and grows with the size of your fish ([`8e374c5`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/8e374c5)).

I also went through a lot of iterations of visual changes, improving the hats and how they fit on the fish ([`cb395a8`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/cb395a8)...[`5a9898c`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/5a9898c)), as well as adding dynamic elements to the menu page like a fish preview that turns to face the mouse hinting at how the game will work ([`558f5f2`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/558f5f2)...[`d83fff5`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/d83fff5)) and a full cosmetic selection window. The in-game map also went through a few complete redesigns, first making it more neon ([`67a0a3b`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/67a0a3b)) before deciding a pond-forward look suited the game better ([`8e374c5`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/8e374c5)). I still decided to keep the background grid in the water because of its specific resemblance to other .io games. What ended up really selling the pond look was adding a blue tint and a ripple effect sweeping over the underwater part of the scene. I then also turned the random puddle ripple effect into a mouse-following trail that makes it feel like you're dragging something across the water's surface that your fish then decides to follow ([`1a4b8dc`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/1a4b8dc)...[`23276e7`](https://github.com/comp4020-agentic-coding-studio/comp4020-final-quackyduck826/commit/23276e7)), which also fits with only being able to see ripples caused by your own cursor and not other fishes' guiding trails.
